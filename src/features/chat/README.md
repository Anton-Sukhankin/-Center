# AIShtab

## Назначение

Feature `chat` является интеграционным слоем для переносимого ИИ-чата из `chat-transfer-package`. Пользовательское название функции в header интерфейса S.Center — `Ассистент AIShtab`.

Чат должен работать как диалоговый помощник по текущему контексту S.Center: выбранному бизнес-юниту, проекту, очереди, ленте событий, фильтрам, метрикам и открытым деталям.

На текущем этапе выполнены адаптер, техническое подключение переносимого ядра и trigger-кнопка `Задать вопрос` в правой зоне тулбара событий.

## Код

Текущая реализация:

- `scenter-ai-chat-adapter.js` — адаптер S.Center к `window.SCostAIChat`;
- `scenter-ai-chat.css` — локальные переопределения токенов drawer;
- `README.md` — паспорт feature.

Точка входа:

- `src/components/event-toolbar/event-toolbar.js` — кнопка `Задать вопрос` с id `open-scenter-ai-chat`;
- `src/components/event-toolbar/event-toolbar.css` — стиль кнопки по модели `Фильтр`.

Переносимое ядро находится отдельно:

- `chat-transfer-package/src/AIChat.js`;
- `chat-transfer-package/src/AIChat.css`;
- `chat-transfer-package/src/demo-provider.js`.

`chat-transfer-package/adapters/scost-prototype-adapter.js` не должен подключаться в S.Center, потому что завязан на структуру другого проекта.

`chat-transfer-package/src/demo-provider.js` также не подключается в текущий прототип, потому что его ответы относятся к S.Cost/АСОР. Временный demo provider S.Center реализован внутри `scenter-ai-chat-adapter.js`.

## Визуальный слой

Чат открывается как правый viewport-level drawer поверх всего интерфейса S.Center, а не как часть центрального блока событий.

Обязательный контракт верстки:

- mount root `#scenter-ai-chat-root` находится в `index.html` на уровне overlay-слоев и фиксируется на весь viewport;
- `#scenter-ai-chat-root` не должен занимать место в сетке приложения и не должен наследовать clipping от `main-content` или `event-feed-sections`;
- `.ai-drawer` открывается справа поверх dashboard, занимает `570px` по ширине и `100vh` по высоте, имеет собственный `z-index`;
- AI-chat использует viewport-слои `2404` для `#scenter-ai-chat-root` и `2405` для `.ai-drawer`, то есть всегда находится выше глобального `.top-navbar` со слоем `2300` и не должен открываться под header;
- список чатов в левой части переносимого ядра скрыт для S.Center;
- создание нового чата, редактирование и удаление чатов отключены в адаптере S.Center;
- resize-handle скрыт, потому что текущий drawer имеет фиксированную ширину `570px`;
- входящие и исходящие сообщения используют размер `15px` и уплотненный межстрочный интервал `1.3`, чтобы диалог читался крупнее, но оставался компактным;
- title и description в header чата соответствуют масштабу header фильтрации: `1.15rem` для title и `0.85rem` для description;
- description в header чата: `Задайте вопрос по физическим параметрам, срокам или статусу`;
- подложка метафоры в header чата повторяет header-icon фильтрации: `44px` на `44px`, `border-radius: 12px`, фон `#F3F4F6`, muted-цвет иконки;
- после отправки сообщения отображается короткое состояние ожидания `Ассистент анализирует контекст...`; это UX-индикатор обработки запроса, а не показ внутренней цепочки рассуждений модели;
- в пустом состоянии отображаются стартовые карточки быстрых вопросов;
- после выбора быстрого вопроса список сразу скрывается на время ожидания ответа;
- после ответа ассистента формируется новый список быстрых вопросов под последним ответом; вопросы должны быть смысловыми follow-up к конкретному ответу, а не статичным общим набором;
- карточки быстрых вопросов выровнены по ширине входящего AI-сообщения, используют тот же радиус скругления `0 16px 16px 16px` и имеют hover-состояние;
- карточки быстрых вопросов имеют белую заливку по умолчанию;
- расстояние от sender label `Вы` / `Ассистент` до пузыря сообщения составляет `8px`;
- avatar-блок входящего сообщения увеличен до `44px` на `44px` и использует локальный asset `src/features/chat/assets/assistant-avatar.png`;
- поле ввода сообщения сохраняет pill-радиус в минимальном однострочном состоянии, но при росте textarea до многострочного состояния контейнер получает `border-radius: 16px`, чтобы не превращаться в овал;
- заголовок drawer в S.Center отображается как `Ассистент AIShtab`; входящие сообщения от ИИ обозначаются коротким sender label `Ассистент`, без ФИО реального сотрудника;
- дефолтные тексты переносимого ядра S.Cost, подпись пустого состояния, placeholder и sender label переопределяются адаптером;
- закрытый root не перехватывает клики по интерфейсу, открытый drawer принимает клики только внутри панели;
- при открытом чате на `body` есть состояние `scenter-ai-chat-open`, которое блокирует фоновый скролл.

## Данные и зависимости

Адаптер получает данные из текущего прототипа и не создает собственные копии сущностей.

Основные зависимости:

- `window.activeContext`;
- `window.filterState`;
- `window.toolbarState`;
- `window.metricsData`;
- `window.activeMetricId`;
- текущая экранная выборка событий;
- состояние открытого event drawer и filter drawer;
- `window.SCostAIChat`.

Правый блок метрик и metric drawer изолированы в `legacy/isolated/right-metrics-panel/`. Самостоятельный BI-график активен в `src/features/bi/` только как переход из детальной карточки события. Ассистент использует расчетные данные `window.metricsData`, но не должен считать изолированные панель или дерево активной поверхностью интерфейса; при открытии ассистента активный BI закрывается как конфликтующий слой.

История чата в S.Center работает в режиме одной рабочей сессии. Адаптер не загружает и не сохраняет историю переписки в `localStorage`; при закрытии drawer состояние сообщений сбрасывается через `window.SCostAIChat.setState(createInitialWorkspace())`.

Демонстрационный provider S.Center содержит один минимальный детерминированный сценарий: если вопрос пользователя касается переноса РНС по 2-й очереди и каскадного влияния на P&L / чистую прибыль, ассистент возвращает конкретный структурированный ответ по этому инциденту. Во всех остальных случаях provider не привязывает ответ к тексту запроса и случайно выбирает один из пяти демонстрационных сценариев. Каждый ответ возвращает свой набор follow-up вопросов, связанных с темой ответа.

Ответы ассистента должны быть объемными и структурированными: краткий вывод, видимые данные контекста, интерпретация, ограничения прототипа и рекомендуемые следующие проверки. Это имитирует не мгновенную справочную реплику, а результат аналитической сводки S.Center по текущему контексту.

Минимальный детерминированный сценарий:

- вопрос про перенос РНС по 2-й очереди на полгода вперед и влияние на P&L-дерево;
- ответ раскрывает каскад `APTS_SOLD_M2 -> REV_APTS -> REV_CORE -> REVENUE -> GROSS_PROFIT -> OPER_PROFIT -> PBT -> NP_SAMOLET`;
- отдельно описывает рост `FIN_EXPENSES`, угрозы кассового разрыва и действия в интерфейсе: создать задачу, запросить обоснование, открыть график, связаться с подрядчиком, закрепить карточку, изменить приоритет и очистить выборку перед массовым AI-анализом.

Пять случайных демонстрационных сценариев для остальных сообщений:

- текущий статус реализации: стадия контекста, количество событий, соотношение высокого и низкого приоритета, строительная длительность;
- физические характеристики и параметры объекта: количество очередей, расчетный строительный объем, стадия; отдельный справочник жилых домов и корпусов пока отсутствует;
- оперативный фокус событий: количество событий в контексте, высокий/низкий приоритет, закрепленные и исключенные карточки;
- метрики контекста: фокусная финансовая метрика, строительная длительность, объем и правило, что фильтры событий не пересчитывают метрики;
- контрольные этапы и календарные сроки: события с `metricId = GANTT_DATES` и события, в тексте которых есть сроки, даты, РНС, СМР, заселение или окончание работ.

Для промышленной версии нужны дополнительные источники данных: справочник физических характеристик проекта, календарь контрольных этапов по очередям и правила выбора точной даты из графика.

Минимальный контекст чата:

```js
{
  mode: 'dashboard' | 'event-feed' | 'event-detail' | 'filtered-selection',
  contextType: 'bu' | 'project' | 'queue',
  contextId: string,
  contextName: string,
  activeTab: 'today' | 'all' | 'pinned' | 'metrics',
  priorityView: 'high' | 'low',
  searchQuery: string,
  filters: {
    period: string,
    sources: string[],
    priority: 'all' | 'high' | 'low',
    metrics: string[]
  },
  visibleEventIds: string[],
  excludedEventIds: string[],
  pinnedEventIds: string[],
  activeMetricId: string | null,
  activeEventId: string | null
}
```

## Пользовательский путь

Текущий пользовательский путь:

1. Пользователь выбирает бизнес-юнит, проект или очередь.
2. Интерфейс перестраивает шапку, события и метрики.
3. Пользователь нажимает кнопку `Задать вопрос` в правой зоне тулбара событий.
4. Чат открывается справа и получает текущий контекст интерфейса.
5. Пользователь задает вопрос по текущей ситуации.
6. После отправки быстрые вопросы скрываются, пока отображается состояние ожидания.
7. Чат отвечает текстом и формирует под ответом новый перечень быстрых вопросов, связанных с этим ответом.

Кнопка `Задать вопрос` отличается от кнопки `Аналитика`: аналитика формирует отчет по текущей выборке событий, а `AIShtab` поддерживает диалог и уточнения по контексту.

Пользователь также может нажать карточку быстрого вопроса. В этом случае текст вопроса подставляется в поле ввода и отправляется через существующую механику отправки сообщения; исходный список вопросов скрывается до появления ответа ассистента.

Для технической проверки чат также можно открыть программно через `window.scenterChat.open()` или `window.SCostAIChat.open()`.

## Состояния

Целевые состояния:

- `closed` — чат закрыт и не влияет на интерфейс;
- `open` — drawer открыт справа на ширину `570px` и не обрезается центральной лентой событий;
- `session-reset` — при закрытии drawer история текущей переписки очищается;
- `empty-chat` — активный чат без сообщений;
- `filled-chat` — активный чат с историей сообщений;
- `quick-questions` — быстрые вопросы доступны в пустом состоянии и после ответа ассистента как контекстный follow-up к последнему ответу;
- `quick-questions-hidden` — список быстрых вопросов скрыт после отправки вопроса и до завершения ответа ассистента;
- `waiting-response` — ожидание ответа провайдера с UX-индикатором `Ассистент анализирует контекст...`;
- `provider-error` — ошибка провайдера отображена системным сообщением.

## Действия пользователя

На первом интеграционном этапе чат может:

- принимать текстовый вопрос;
- отправлять быстрый вопрос кликом по карточке;
- скрывать список быстрых вопросов до получения ответа;
- показывать новый смысловой список быстрых вопросов под последним ответом ассистента;
- отправлять сообщение;
- показывать ответ;
- закрываться кликом вне панели;
- показывать контекст текущего объекта.

На первом этапе чат не должен:

- создавать новый чат;
- переключать, редактировать или удалять чаты;
- менять собственную ширину через resize;
- сохранять историю нескольких чатов между открытиями drawer;
- создавать реальные задачи;
- менять фильтры;
- изменять приоритет события;
- закреплять или исключать события;
- переключать проект, очередь или метрику;
- отправлять данные во внешние системы.

## Конфликтующие панели

При открытии чата адаптер обрабатывает конфликты:

- закрыть детальную карточку события или передать ее `eventId` в контекст;
- закрыть drawer структуры метрик или сохранить выбранную метрику в контексте;
- определить правило для BI-модалки: закрывать или не открывать чат поверх BI;
- сохранить состояние фильтров;
- не сбрасывать floating action bar, если пользователь находится в режиме фильтрации.

## Связь с `window.*`

Feature должна сохранить существующие публичные интерфейсы S.Center.

Будущие публичные точки feature:

- `window.SCostAIChat` — API переносимого ядра;
- `window.scenterChat` — адаптерный namespace S.Center, если будет принято решение не размещать вспомогательные функции в `src/app/app.js`;
- `window.scenterChatProvider` — провайдер сообщений;
- `window.scenterChatStorage` — слой хранения истории, если потребуется.

Изменение существующих `window.filterState`, `window.toolbarState`, `window.metricsData`, `window.aiInsights` не входит в первый этап интеграции.

## Ограничения прототипа

На текущем этапе чат технически подключен и имеет пользовательскую точку входа в тулбаре событий. Реальный provider и продуктовые action-кнопки остаются будущими этапами.

Внутренний demo provider допустим только для проверки интерфейса до появления реального API. Кроме минимального детерминированного P&L-сценария, его ответы выбираются случайно из пяти сценариев и не считаются продуктовой AI/ML-аналитикой S.Center.

## Будущие требования

В будущих этапах нужно определить:

- реальный провайдер сообщений;
- правила хранения истории чатов;
- права доступа к данным, которые передаются в чат;
- запуск чата из карточки события или drawer события;
- action-кнопки в ответах чата;
- связь чата с результатами массовой AI-аналитики.

## Когда обновлять документ

Документ нужно обновлять, если:

- меняется назначение чата;
- меняется состав `getContext`;
- меняются разрешенные действия чата;
- меняется точка входа;
- меняется слой отображения, ширина, высота, `z-index` или способ mount root;
- меняется правило закрытия конфликтующих панелей;
- подключается реальный provider;
- меняется связь с `AI-аналитикой`, событиями, фильтрами или метриками.
