# Фильтры событий

Панель использует [общий переход](../../ui/README.md) от кнопки тулбара и обратно. «Применить» применяет условия сразу, окно снимается после выхода; повторное действие в этот момент блокируется.

Дерево в разделе «Метрики» использует цвета и переход раскрытия ветвей окна [«Структура метрик»](../metrics/README.md). Обычные строки прозрачны, при наведении и выборе появляется общая подложка. При включённом уменьшении движения ветви меняются без анимации. Скрытые потомки недоступны для фокуса, а чекбоксы сохраняют выбор при сворачивании.

В [React-версии фильтра](../../../react/event-tools/Filters.jsx) черновик применяется при подтверждении. Поиск по дереву метрик сохраняет путь к найденным узлам. Выборка ленты обновляется отдельно от агрегатов метрик в [React-оболочке](../../../react/app/App.jsx).

## Назначение

Feature `filters` отвечает за настройку выдачи событий внутри активного контекста.

## Код

[Filters](../../../react/event-tools/Filters.jsx) — React-панель. Стили — `filter-drawer.css` и `event-tools.css`.

## Источник данных

Фильтр берет данные из общего слоя:

- источники событий: `appData.getEventSources()`;
- дерево метрик: подготовленное дерево `metrics` активного контекста;
- текущее состояние фильтра: `filters` в App.

## Пространственный контракт текущей реализации

Фильтр открывается поверх подложки без выезда: отступ сверху, справа и снизу 24 px (8 px на узком экране), максимальная ширина 800 px. Высота не зависит от раздела. Навигатор переключает источники, приоритет, период и метрики; прокручивается содержимое, шапка и футер остаются на месте. На узком экране навигация над содержимым.

Filter drawer использует общий viewport-слой правых панелей: overlay `2400`, сама панель `2401`. Эти значения выше глобального `.top-navbar` со слоем `2300`, поэтому фильтр должен открываться поверх header, а не под ним.

В шапке без иконки рядом с названием (8 px) показано число уже применённых условий. Счётчики разделов учитывают черновик. В дереве шеврон раскрывает ветвь, название или чекбокс выбирает её с потомками без открытия графика. «Сбросить всё» очищает черновик, «Применить» подтверждает его. «Отмена», общая кнопка Lightline «Закрыть», Escape и клик по подложке отменяют изменения и возвращают фокус к кнопке фильтров.

## Пользовательский путь

Пользователь открывает одну и ту же панель фильтра из `Сегодня` или `Все события`, выбирает источник, приоритет, период или метрику и применяет условия к текущей выдаче. В `Сегодня` условия работают только по событиям текущего дня. Применение и выход из режима фильтрации сохраняют вкладку `Сегодня`.

Панель фильтрации не должна срабатывать мгновенно при каждом клике. Пользователь сначала настраивает параметры, затем применяет их отдельным действием. Это важно, потому что рабочая база событий может быть большой, а фильтрация часто используется как подготовка массива для массового ИИ-анализа.

## Сценарий на странице `Все события`

На странице `Все события` фильтры используются не только для просмотра карточек, но и для формирования точной аналитической выборки перед массовым ИИ-анализом.

Пользовательский путь:

1. Пользователь настраивает атрибутные фильтры: период времени, продукт-источник, приоритет события и метрику влияния. Текстового поиска событий в тулбаре нет.
2. После применения фильтров система показывает список карточек внутри активного структурного контекста.
3. Пользователь вручную исключает нерелевантные карточки через крестик или иконку удаления из выдачи. Карточки скрываются только из текущей экранной выборки и не удаляются из базы данных.
4. Пользователь нажимает `Аналитика` или `Анализировать`.
5. ИИ получает только очищенный массив событий, оставшийся на экране, и формирует сводный вывод.

Типовой пример: пользователь ищет события по подрядчику `ИП Иванов`, фильтр может случайно захватить карточки другого подрядчика с похожим именем. Перед запуском ИИ-анализа пользователь должен исключить такие карточки, чтобы итоговый вывод не был искажен нерелевантными событиями.

## Важные правила

Фильтрация применяется внутри активного контекста дерева. Выбор нового бизнес-юнита, проекта или очереди является базовым фильтром системы: он меняет адрес данных, отсекает нерелевантные события и обновляет метрики выбранного уровня. Пользовательские атрибутные фильтры при смене контекста сбрасываются.

Исключение событий из выдачи активно только при наличии примененных фильтров.

Левое структурное дерево является первичным фильтром. Если выбран бизнес-юнит, проект или очередь, все пользовательские фильтры применяются только внутри этого адреса.

Итоговая выдача после применения фильтров и ручного исключения нерелевантных карточек становится контекстом для кнопки `Аналитика`. ИИ должен анализировать только события, оставшиеся в текущей экранной выборке.

Атрибутные фильтры ленты не пересчитывают финансовые или строительные метрики. Они влияют только на отображение карточек и состав массива событий для ИИ-анализа. Числовые показатели меняются при навигации по структурному дереву: бизнес-юнит агрегирует проекты, проект агрегирует очереди, очередь показывает собственные значения.

## Обязательные параметры фильтрации

| Параметр | Назначение |
| --- | --- |
| Период времени | Фильтрация событий за день, неделю, месяц или другой заданный период. В целевом интерфейсе может быть реализован через date picker. |
| Продукт / источник | Выбор системы, из которой пришли события, например S.Pass, Control, Gantt или другой продукт. |
| Метрика влияния | Выбор нижней метрики, на которую влияет событие, например расходы на строительство. |
| Приоритет | Выбор статуса события: высокий приоритет или остальные события. |

## Непустая выдача

В системе нет жесткого требования, что каждое отдельное значение каждого фильтра всегда должно давать непустую выдачу. Но базовые сценарии не должны приводить пользователя к пустому экрану без причины:

- вкладка оперативных событий за текущий или вчерашний день предполагается заполненной, потому что события со стройки появляются ежедневно;
- вкладка `Все события` по умолчанию должна использовать период больше одного дня, например неделю, чтобы сразу показывать накопленный массив;
- сброс пользовательских фильтров возвращает исходную выдачу `Сегодня` или `Все события` в активном контексте, если в ней есть доступные события.

## Публичные интерфейсы

`Filters` получает `filters`, `metrics`, `sources`, `onApply` и `onClose`. Черновик принадлежит панели. App объединяет подтвержденные значения с состоянием выдачи.

## Зависимости

[App](../../../react/app/App.jsx) передает каталог источников и дерево активного контекста. [feedModel](../../../react/events/feedModel.js) рассчитывает выдачу и счетчики по примененным значениям.

## Ограничения прототипа и будущие требования

Сейчас фильтры работают по демонстрационному массиву событий внутри активного контекста. В будущем feature должен поддерживать полноценный date picker, большие выборки из базы, сохранение пользовательских пресетов и передачу очищенной выборки в реальный AI-анализ.

## Acceptance

- drawer открывается из EventToolbar и закрывается кнопкой, overlay и `Escape`;
- draft не меняет ленту до применения;
- apply синхронизирует выдачу, toolbar и floating bar;
- reset возвращает исходную непустую выборку доступного контекста;
- режим ленты, период, источники, приоритеты и метрики пересекаются предсказуемо;
- исключенные Event не возвращаются в текущий AI-массив без явного undo/reset;
- drawer не оставляет scroll/focus trap после закрытия.

Автоматического локального `*.test.mjs` для feature сейчас нет.
