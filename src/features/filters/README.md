# Фильтры событий

## Назначение

Feature `filters` отвечает за настройку выдачи событий внутри активного контекста.

## Код

- `filter-drawer.js`;
- `filter-drawer.css`.

## Источник данных

Фильтр берет данные из общего слоя:

- источники событий: `appData.getEventSources()`;
- дерево метрик: `appData.getMetricSelectorTree(window.metricsData)`;
- текущее состояние фильтра: `window.filterState`.

## Пользовательский путь

Пользователь открывает панель фильтра, выбирает источник, приоритет, период или метрику, применяет фильтр и видит обновленную ленту событий.

Панель фильтрации не должна срабатывать мгновенно при каждом клике. Пользователь сначала настраивает параметры, затем применяет их отдельным действием. Это важно, потому что рабочая база событий может быть большой, а фильтрация часто используется как подготовка массива для массового ИИ-анализа.

## Сценарий на странице `Все события`

На странице `Все события` фильтры используются не только для просмотра карточек, но и для формирования точной аналитической выборки перед массовым ИИ-анализом.

Пользовательский путь:

1. Пользователь настраивает текстовый поиск или атрибутные фильтры: период времени, продукт-источник, приоритет события и метрику влияния.
2. После применения фильтров система показывает список карточек внутри активного структурного контекста.
3. Пользователь вручную исключает нерелевантные карточки через крестик или иконку удаления из выдачи. Карточки скрываются только из текущей экранной выборки и не удаляются из базы данных.
4. Пользователь нажимает `Аналитика` или `Анализировать`.
5. ИИ получает только очищенный массив событий, оставшийся на экране, и формирует сводный вывод.

Типовой пример: пользователь ищет события по подрядчику `ИП Иванов`, фильтр может случайно захватить карточки другого подрядчика с похожим именем. Перед запуском ИИ-анализа пользователь должен исключить такие карточки, чтобы итоговый вывод не был искажен нерелевантными событиями.

## Важные правила

Фильтрация применяется внутри активного контекста дерева. Выбор нового бизнес-юнита, проекта или очереди является базовым фильтром системы: он меняет адрес данных, отсекает нерелевантные события и обновляет метрики выбранного уровня. Пользовательские атрибутные фильтры при смене контекста сбрасываются.

Исключение событий из выдачи активно только при наличии примененных фильтров.

Левое структурное дерево является первичным фильтром. Если выбран бизнес-юнит, проект или очередь, все пользовательские фильтры и текстовый поиск применяются только внутри этого адреса.

Итоговая выдача после применения фильтров и ручного исключения нерелевантных карточек становится контекстом для кнопки `Аналитика`. ИИ должен анализировать только события, оставшиеся в текущей экранной выборке.

Атрибутные фильтры ленты не пересчитывают финансовые или строительные метрики. Они влияют только на отображение карточек и состав массива событий для ИИ-анализа. Числовые показатели меняются при навигации по структурному дереву: бизнес-юнит агрегирует проекты, проект агрегирует очереди, очередь показывает собственные значения.

## Обязательные параметры фильтрации

| Параметр | Назначение |
| --- | --- |
| Период времени | Фильтрация событий за день, неделю, месяц или другой заданный период. В целевом интерфейсе может быть реализован через date picker. |
| Продукт / источник | Выбор системы, из которой пришли события, например S.Pass, Control, Gantt или другой продукт. |
| Метрика влияния | Выбор нижней метрики, на которую влияет событие, например расходы на строительство. |
| Приоритет | Выбор статуса события: высокий приоритет или остальные события. |
| Текстовый поиск | Поиск по содержимому события, которое не вынесено в отдельный атрибут, например по подрядчику или фамилии. |

## Непустая выдача

В системе нет жесткого требования, что каждое отдельное значение каждого фильтра всегда должно давать непустую выдачу. Но базовые сценарии не должны приводить пользователя к пустому экрану без причины:

- вкладка оперативных событий за текущий или вчерашний день предполагается заполненной, потому что события со стройки появляются ежедневно;
- вкладка `Все события` по умолчанию должна использовать период больше одного дня, например неделю, чтобы сразу показывать накопленный массив;
- сброс всех пользовательских фильтров должен возвращать непустую историческую выдачу внутри активного контекста, если у пользователя есть доступные события.

## Когда обновлять документ

## Ограничения прототипа и будущие требования

Сейчас фильтры работают по демонстрационному массиву событий внутри активного контекста. В будущем feature должен поддерживать полноценный date picker, большие выборки из базы, сохранение пользовательских пресетов и передачу очищенной выборки в реальный AI-анализ.
