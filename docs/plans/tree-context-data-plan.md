# Контекстное дерево проектов, событий и метрик

## Назначение

Документ фиксирует следующий слой структуры прототипа: связь между боковым деревом, выбранным контекстом, событиями центральной области и метриками правой панели.

Основной принцип: пользователь выбирает бизнес-юнит, проект или очередь, а интерфейс показывает данные только в границах выбранного контекста.

## Статус реализации

Этап первичной реализации выполнен:

- старый план карточек перенесен из `docs/plans/` в `docs/archive/`;
- создан слой `src/data/project-structure.js`;
- `index.html` подключает структуру проектов до `src/app/app.js`;
- основной сценарий приложения получает дерево из слоя данных;
- выбор узла дерева обновляет активный контекст;
- события фильтруются внутри выбранного контекста;
- метрики правой панели рассчитываются на основании событий выбранного контекста.

Дополнительное наполнение дерева выполнено:

- бизнес-юниты без дочерних узлов получили проекты и очереди;
- каждая очередь содержит события для вкладок “Сегодня” и “Все события”;
- на уровне проекта отображается сумма событий всех дочерних очередей;
- на уровне бизнес-юнита отображается сумма событий всех дочерних проектов;
- в каждой очереди есть события высокого и низкого приоритета.

## Модель данных

### Дерево

Дерево хранится в `src/data/project-structure.js`.

Уровни дерева:

- бизнес-юнит;
- проект;
- очередь.

Каждый узел содержит `id`, `name`, `type`, а проектные узлы дополнительно содержат `headerAttributes` для шапки интерфейса.

### Активный контекст

Активный контекст описывает выбранный узел и область данных, которая должна отображаться в интерфейсе.

Состав контекста:

- `type` — тип выбранного узла: `bu`, `project`, `queue`;
- `id` — идентификатор выбранного узла;
- `projectId` — основной проект для шапки и очереди;
- `projectIds` — проекты, входящие в область выборки;
- `queueIds` — очереди, входящие в область выборки;
- `businessUnitIds` — бизнес-юниты, входящие в область выборки.

Правила:

- бизнес-юнит включает все дочерние проекты и очереди;
- проект включает все свои очереди;
- очередь включает только саму себя.

### События

События хранятся в `src/data/app-data.js`.

Каждое событие получает контекстные атрибуты:

- `businessUnitId`;
- `projectId`;
- `projectName`;
- `queueId`;
- `queue`.

Центральная лента работает по последовательности:

1. Сначала события ограничиваются активным контекстом.
2. Затем применяются пользовательские фильтры.
3. Затем применяется выбранная вкладка: “Сегодня”, “Все”, “Закрепленные”.
4. После этого события группируются по приоритету.

### Метрики

Базовое дерево финансовых метрик остается единым.

Для выбранного контекста создается расчетная копия дерева. В целевой модели события используются для прогнозного влияния, риска и аналитики, но исключение события из выдачи не должно менять числовые значения метрик:

- берутся события выбранного контекста;
- каждое событие с `metricId` и `impactValue` связывается с целевой метрикой как источник прогнозного влияния;
- влияние может отображаться в карточке события и учитываться в ИИ-анализе риска;
- исключенные события убираются из текущей экранной выборки и массива для массового ИИ-анализа;
- исключенные события не меняют факт, план, прогноз или отклонения финансовых и строительных метрик.

## Правила переключения

При выборе нового узла дерева:

- обновляется активный контекст;
- сбрасываются фильтры и исключения;
- заново выбираются события;
- пересчитываются метрики;
- перерисовываются шапка, центральная лента, дерево и правая панель.

Вкладка событий сохраняется. Если вкладка “Закрепленные” пуста, интерфейс показывает заглушку.

## Проверка

После реализации нужно проверить:

- выбор бизнес-юнита меняет шапку, события и метрики;
- выбор проекта меняет шапку, события и метрики;
- выбор очереди меняет шапку, события и метрики;
- в выбранном контексте есть карточки событий;
- фильтры применяются только внутри выбранного контекста;
- закрепление работает в текущей выборке;
- исключение работает только при активных фильтрах;
- правая панель и дерево метрик используют один расчетный источник.

Проверка плотности данных:

- количество очередей: 47;
- каждая очередь во вкладке “Сегодня”: 27 событий;
- каждая очередь во вкладке “Все события”: от 42 до 44 событий;
- каждая очередь содержит высокий и низкий приоритет в обеих вкладках;
- все бизнес-юниты раскрываются до уровня проекта и очереди.

## Контекстный расчет финансовых метрик

Этап расчета финансовых метрик из событий был реализован как прототипная аппроксимация. После уточнения предметной модели целевое правило фиксируется так:

- каждое событие получает расчетный блок `metricValues`;
- расчетный блок содержит `fact`, `plan`, `forecast`, `previousMonth`;
- `impactValue` сохранен для карточек события, обратной совместимости и визуализации прогнозируемого влияния;
- базовые значения финансовых и строительных метрик не должны меняться при исключении события из выдачи;
- исключенные события не участвуют в текущей пользовательской выборке для массового ИИ-анализа;
- события, ссылающиеся на родительские метрики, стабильно переназначаются на дочерние leaf-метрики;
- родительские метрики агрегируют дочерние `fact`, `plan`, `forecast`, `previousMonth`, `delta`;
- `delta` считается как `fact - plan`;
- `deltaPrevMonth` считается как процентное отклонение `fact` от `previousMonth`;
- правая панель и drawer структуры метрик используют один источник `window.metricsData`.

Проверка расчетной модели:

- для всех 47 очередей есть активные leaf-метрики;
- соседние очереди получают разные значения метрик;
- родительские метрики равны сумме дочерних метрик;
- проект равен сумме всех своих очередей;
- бизнес-юнит равен сумме всех своих проектов.
