# Feature «Объекты»

## Назначение

`objects.js` — нативная classic-script/IIFE реализация раздела «Объекты». Feature перенесен из принятого временного React/Vite-стенда в активный прототип без React runtime, iframe и ES-модулей. После продуктовой приемки дублирующий стенд удален; исходные визуальные материалы сохранены в `docs/reference/objects/`.

Базовые table-shell, семантика границ и lifecycle локальных scroll-индикаторов вынесены в `src/components/construction-table/` и переиспользуются проектной `Сводкой`. Данные, колонки, раскрытие и фильтрация раздела `Объекты` остаются feature-specific; публичный `window.SCenterObjects` не изменен.

Раздел показывает карточки пяти объектов, компактный паспорт выбранного объекта, инструменты фильтрации и выгрузки, а также двухуровневое дерево `WorkGroup → WorkType`.

## Подключение

Порядок подключения в `index.html` должен оставаться явным:

1. `src/data/construction-objects-data.js`;
2. `src/data/objects-data.js`;
3. `src/components/construction-object-selector/construction-object-selector.js` и его CSS;
4. `src/features/objects/objects.css`;
5. `src/features/objects/objects.js`;
6. `src/app/app.js`.

Контейнер feature имеет `id="objects-root"`; CSS изолирован этим root и префиксом `obj-`. Shared selector использует собственный документированный префикс `cos-`.

## Публичный lifecycle

`window.SCenterObjects` предоставляет:

- `mount(root, { context })` — связывает обработчики, получает модель и выполняет первый render;
- `setContext(context)` — обновляет проектный контекст;
- `show()` — показывает уже смонтированный раздел без сброса локального состояния;
- `hide()` — закрывает dialog/drag/toast и скрывает раздел, сохраняя выбор, фильтры и раскрытие;
- `closeOverlays()` — закрывает filter dialog и активный drag;
- `destroy()` — удаляет DOM, listeners, `ResizeObserver`, drag и таймеры.

Повторный `mount` в тот же root не дублирует обработчики. `mount` в другой root сначала уничтожает прежний экземпляр.

## Источники данных

Feature не создает собственные копии Project, Queue, ConstructionObject или строк работ. Модель поступает из `window.objectsData.getForContext(context)`:

- `project` разрешается по `id` / `projectId`;
- `queue` — по родительскому `projectId`;
- `business unit` и неизвестный проект возвращают `unsupported-context`, stale-данные очищаются;
- смена `projectId` сбрасывает объект, фильтры, раскрытие и scroll;
- смена очереди внутри одного проекта сохраняет локальное состояние.

Карточки передаются в `window.SCenterComponents.renderConstructionObjectSelector(cards, options)`. Внутри feature есть безопасный временный fallback, который строится из тех же объектов текущей модели и не содержит собственной копии сущностей. Клавиатурная навигация shared selector делегируется `handleConstructionObjectSelectorKeydown`.

## Локальное состояние

Feature хранит только presentation state текущей загрузки страницы:

- `activeObjectId`;
- `expandedGroups`;
- `quickStatus`;
- `appliedFilters` и `draftFilters`;
- состояние filter dialog;
- короткое `aria-live` announcement.

При выборе другого объекта открывается его первая группа, а quick/applied/draft filters сбрасываются. Выбор объекта не синхронизируется неявно с шахматкой и не расширяет `window.activeContext`.

## Поведение

- в верхней левой части рабочей области раздела всегда отображается локальный заголовок `Объекты` размером `24px / 600`; он отделяет выбранный пункт dropdown от служебного title таблицы `Группы и виды работ`;
- карточки поддерживают roving tabs, стрелки, `Home` и `End`;
- description под названием объекта в карточке показывает параметры объекта из нижней meta-строки (`этажи/секции`, `уровни/зоны`) вместо типа объекта; отдельная нижняя meta-строка не выводится;
- карточка объекта разделена на верхний информационный блок с нижним border и нижний блок из двух зон: круговая готовность с процентом и пояснение к ходу работ `14px`, отделенное вертикальным border от зоны готовности;
- quick status пересекается с примененными status/contractor/search filters;
- родительская группа сохраняется в выборке, если совпала сама группа либо ее дочерняя работа;
- раскрытие строки управляет только отображением дочерних строк, экспорт использует всю текущую отфильтрованную выборку;
- dialog поддерживает autofocus, focus trap, `Escape`, cancel, apply, reset, backdrop и возврат фокуса; filter dialog является right-side viewport overlay и использует общий слой `2400`, чтобы открываться поверх глобального `.top-navbar`;
- CSV кодируется UTF-8 BOM, разделяется `;`, использует CRLF и экранирование двойных кавычек; временный `ObjectURL` отзывается;
- таблица содержит отдельную disclosure-колонку, `Плановый срок → С / По`, одинарный header `Степень готовности`, sticky header и пустой sticky footer; обе закрепленные ячейки header находятся выше sticky-ячеек строк, поэтому disclosure-индикаторы не перекрывают пустую ячейку title при вертикальном скролле;
- рабочая зона под карточками объектов имеет явный title `Группы и виды работ`; title стоит над параметрами, быстрым фильтром, кнопками и таблицей, потому что маркирует весь блок управления работами; используется единый служебный стиль `12px / 600`, uppercase, тёмно-серый `#475569`.
- системные scrollbars скрыты; vertical/horizontal indicators отражают только локальный overflow, перетаскиваются и очищают document listeners;
- позиция внутренней таблицы сохраняется при локальном render и переключении очереди того же проекта, но сбрасывается при выборе другого объекта или проекта;
- длинные названия работ и подрядчиков сокращаются многоточием и доступны через `title`;
- колонки подрядчика и готовности поровну получают остаточную ширину, шкала прогресса растягивается вместе с ячейкой.

## Визуальные инварианты

- пять параметров имеют одинаковую для всех объектов ширину `130 / 114 / 159 / 149 / 157px`, то есть каждый подблок расширен на `16px`;
- типографика строки параметров синхронизирована с блоком параметров «Шахматки»: лейбл `12px / 400`, значение `16px / 600`; этот же контракт используется для значений верхней сводки «Шахматки»;
- высота строки и каждого подблока параметров стандартизирована с «Шахматкой»: `73px`; вертикальный padding параметров — `16px`;
- подблоки параметров не имеют внутренних border-разделителей; внешний border остается только у контейнера параметров.
- расстояние между блоком параметров/действий и таблицей групп и видов работ составляет `4px`;
- таблица использует `14px`, наименования групп — `font-weight: 600`;
- все header/data cells белые и имеют правый border;
- footer пуст, закреплен снизу и имеет только верхний border;
- горизонтальный indicator находится на `8px` выше footer;
- собственные selectors feature имеют `obj-` prefix и ограничены `#objects-root`.

## Текущие ограничения

- данные демонстрационные; готовность и статусы не являются промышленным расчетом;
- passport geometry объектов и matrix geometry шахматки пока остаются разными demo-view-model;
- содержимое row menu не согласовано, поэтому кнопка выводит announcement без фиктивных действий;
- состояние не сохраняется после перезагрузки и не отражается в URL;
- промышленный экспорт, роли, права и backend API находятся вне текущего этапа.

## Минимальная проверка

После изменения нужно проверить:

- `node --check src/features/objects/objects.js`;
- вход в `Объекты` из header и возврат в dashboard/шахматку;
- context project → queue того же проекта → другой project → business unit;
- пять карточек мышью и клавиатурой;
- раскрытие, quick/applied filters, no-results и reset;
- dialog keyboard/focus/backdrop;
- CSV текущей выборки;
- sticky header/footer, оба scroll indicator и drag cleanup;
- отсутствие page-level overflow и console warning/error.
