# Текущий audit-checkpoint документации

## Статус документа

- Класс: доказательный checkpoint.
- Временной слой: текущий снимок на 2026-08-13.
- Область: активная документационная система S.Center без архивов, evidence, visual reference, изолированного legacy-модуля и временного методологического референса.
- Владелец обновления: основной агент системной документационной задачи.
- Нормативность: документ подтверждает результат проверки, но не определяет продуктовое поведение.

## Итог

Документационная система работает в смешанном режиме с явным разделением текущей реализации, целевой модели, переходных планов и истории. Для каждого проверенного правила назначен постоянный владелец; обязательная структура `01/02/03`, отдельные business-analysis/testing-каталоги и параллельная карта связи с кодом не введены, поскольку их функции на текущем масштабе выполняют существующие спецификации, локальные паспорта, карты и матрица соответствия.

На момент checkpoint нет открытых P0/P1-конфликтов источников, битых относительных Markdown-ссылок, незарегистрированных активных планов, точных дублей активных файлов или orphan visual references.

## Принятые механизмы

| Механизм | Текущий владелец или реализация |
| --- | --- |
| Иерархия источников и смешанный режим | `AGENTS.md`, `docs/README.md`, `docs/documentation-standards.md` |
| Локальный контракт компонента или feature | README соответствующего каталога `src/components/` или `src/features/` |
| Структура, поведение, состояния, пространственные и межкомпонентные контракты | разделы локального паспорта; отдельные файлы создаются только при независимом жизненном цикле |
| Сквозной путь Event → Task | `docs/decision-actions.md`, `src/features/tasks/README.md`, `src/components/event-card/README.md` |
| Общие сущности и данные | `docs/entity-model.md`, `src/data/README.md` |
| Связь с реализацией и каскад обновления | `docs/component-map.md`, `docs/component-impact-map.md`, локальные паспорта |
| Testing и acceptance | локальные разделы `Acceptance`, компактный реестр в `docs/README.md`, существующие `*.test.mjs` |
| Visual references и evidence | локальные manifest в `docs/reference/` и `docs/evidence/` |
| Автоматическая структурная проверка | `scripts/check-documentation.mjs` и mutation-тесты рядом |

## Пилот и влияние на контекст

Пилот охватил простой `navigation-tree-item`, пространственно сложный AIShtab и сквозной сценарий Event → Task. Для выборки измерен размер входного текстового контекста: полный набор общих документов сравнивался с быстрым маршрутом, локальным паспортом и только релевантными строками карт.

| Объект | Полный маршрут | Минимальный маршрут | Сокращение |
| --- | ---: | ---: | ---: |
| `navigation-tree-item` | 75 507 байт | 11 834 байта | 84,3% |
| AIShtab | 94 640 байт | 31 183 байта | 67,1% |
| Event → Task | 83 559 байт | 27 341 байт | 67,3% |

Результат превышает принятый для пилота порог 25% без потери локального контракта, владельцев сущностей и каскада проверок.

## Выполненная приёмка

- Автоматический checker: `errors=0`, `warnings=0` после финального удаления временных материалов.
- Mutation-тесты checker: четыре негативных сценария — битая ссылка, отсутствующий локальный README, незарегистрированный активный план и orphan visual reference.
- Активные component/feature-паспорта: 15 из 15 содержат локальный acceptance-маршрут.
- Активные планы: 3 из 3 зарегистрированы; архивные планы: 11 из 11 зарегистрированы.
- Runtime desktop: переход в очередь, открытие события, валидация обязательных полей, выбор ответственного, создание связанной in-memory задачи и открытие AIShtab подтверждены.
- Runtime narrow: при viewport `720×900` AIShtab открывается, `documentElement.scrollWidth` и `body.scrollWidth` равны 720 px.
- Ошибки консоли на desktop-smoke не обнаружены.

## Условия актуализации

Checkpoint обновляется после изменения иерархии источников, формата локального паспорта, состава автоматического checker или массовой миграции документации. Обычное продуктовое изменение обновляет своих постоянных владельцев и не требует переписывать этот отчет. Предыдущую версию checkpoint не следует использовать как backlog; дальнейшие требования фиксируются в активном roadmap или профильном плане.
