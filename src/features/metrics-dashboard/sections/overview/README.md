# MetricsDashboard: «Общие»

## Статус и назначение

Вкладка `Общие` — текущая реализованная часть `MetricsDashboard`. Она показывает проектную или очередную сводку по срокам, контрольным этапам и бюджетным основаниям. Общая оболочка, контекст и переключение вкладок принадлежат родительскому [MetricsDashboard](../../README.md).

## Граница подраздела

Подраздел владеет только содержимым `tabpanel` после выбора `Общие`:

- четырьмя KPI-карточками сроков;
- шкалой контрольных этапов;
- тремя карточками бюджетных оснований и попарных сравнений.

Подраздел не владеет строкой внутренних вкладок, активным проектом или очередью, loading-переходом общего shell и возвратом к ленте событий.

## Текущие данные и расчеты

Содержимое получает подготовленную демонстрационную view model из `src/data/metrics-dashboard-data.js`. Проект и очередь используют разные `contextKey`; бизнес-юнит не получает содержимое этой вкладки и видит состояние `unsupported-context` родительского feature.

Показанные сроки, этапы, бюджеты, сравнения и прогноз являются устойчивыми demo-данными. Они проверяют интерфейс, но не подтверждают промышленные источники или методику. План перехода к реальным данным находится в `docs/plans/metrics-real-data-integration-plan.md`.

## Видимая структура

1. Сводка сроков: плановая и прогнозная длительность, отклонение, прогнозное завершение.
2. Контрольные этапы: полная шкала по умолчанию и временное сворачивание до фокусного набора.
3. Бюджетные основания: целевая стоимость, договорная стоимость и фактически принятый объем с попарными сравнениями.

Главные значения четырех KPI-карточек и трех карточек бюджетных оснований отображаются размером `24px`. Нижние значения попарных сравнений бюджетов сохраняют размер `18px`.

## Поведение и состояния

- при выборе `Общие` обновляется единственный `tabpanel`, а строка вкладок и корневой shell остаются смонтированными;
- смена проекта или очереди заменяет значения без промежуточного отображения данных предыдущего контекста;
- `Свернуть` сокращает только шкалу этапов и не изменяет view model;
- возвращение на вкладку после другой внутренней вкладки восстанавливает текущий контекст родительского feature.

## Приемка

- четыре KPI, этапы и три бюджетные карточки отображаются для проекта и очереди;
- смена контекста не оставляет stale-значения;
- бизнес-юнит не получает project-only показатели;
- содержимое перестраивается в две и одну колонку без page-level overflow;
- демонстрационные данные не описываются как промышленная методика.

## Когда обновлять документ

Документ обновляется при изменении состава, назначения, данных, расчетов, состояний или пользовательского пути вкладки `Общие`. Изменения общей оболочки документируются в родительском паспорте.
