# Контекстный расчет строительных показателей

## Назначение

Документ фиксирует выполненный этап: правый блок `Строительные показатели` теперь зависит от выбранного узла бокового дерева.

Строительные показатели работают по тому же принципу, что и финансовые метрики:

- очередь показывает собственные значения;
- проект показывает сумму значений всех своих очередей;
- бизнес-юнит показывает сумму значений всех проектов и очередей внутри себя.

## Состав показателей

В текущем прототипе расчетная модель применяется к двум карточкам правой панели:

- `Длительность проекта`;
- `Объём проекта`.

Для каждой очереди формируются стабильные демонстрационные значения:

- плановая длительность;
- прогнозная длительность;
- отклонение прогноза от плана по длительности;
- плановый объем;
- прогнозный объем;
- отклонение прогноза от плана по объему.

## Правила агрегации

Базовая расчетная единица — очередь.

Проект не хранит независимые значения строительных показателей. Он агрегирует значения всех дочерних очередей.

Бизнес-юнит также не хранит независимые значения. Он агрегирует значения всех очередей внутри всех дочерних проектов.

Таким образом, при переходе от очереди к проекту и от проекта к бизнес-юниту значения увеличиваются как сводные.

## Источник данных

Источник расчета находится в `src/data/app-data.js`.

Публичная функция слоя данных:

- `getConstructionMetricsForContext(context)`.

Функция принимает активный контекст дерева и возвращает расчетные значения для карточек строительных показателей.

## Компоненты-потребители

Значения потребляет правая панель интерфейса в `src/app/app.js`.

Визуальный компонент карточки не менялся:

- `src/components/construction-metric-card/construction-metric-card.js`.

Компонент остается универсальным: он получает готовые значения и отрисовывает карточку.

## Критерии готовности

Этап считается выполненным, если:

- при выборе очереди карточки строительных показателей показывают значения этой очереди;
- при выборе проекта карточки показывают сумму очередей проекта;
- при выборе бизнес-юнита карточки показывают сумму всех очередей бизнес-юнита;
- соседние очереди имеют разные значения;
- визуальная структура правой панели не меняется.

## Исправление после пользовательской проверки

После первичной реализации расчетный слой работал корректно, но правый блок строительных показателей не обновлялся при переключении узла дерева.

Причина: сценарий выбора бизнес-юнита, проекта или очереди обновлял шапку, ленту событий и финансовые метрики, но не вызывал перерисовку строительных карточек.

Исправление: в сценарий `setActiveEntity` добавлено обновление блока `Строительные показатели`.
