# Feature создания задачи

## Назначение

Feature реализует текущий демонстрационный сценарий создания, редактирования и удаления задачи на основании события. Он использует существующий `#event-drawer`: отдельный drawer задачи не создаётся.

Feature владеет формой задачи, выбором ответственного, карточками связанных задач и переходами между task-режимами. Он не владеет сущностью исходного события, общим открытием event drawer, постоянным хранением, правами или workflow задачи.

Текущая реализация поддерживает три режима контейнера:

- `event-detail` — детальная карточка события;
- `task-create` — создание задачи;
- `task-edit` — просмотр и редактирование созданной задачи.

Задачи хранятся в памяти страницы через `window.taskData`. Backend, сохранение после перезагрузки, статусы workflow, история изменений и права доступа в этот feature не входят.

## Реализация и стили

- `task-drawer.js` — controller, renderer формы, карточек и окна команды;
- `task-drawer.css` — локальные формы, dropdown, team-layer и responsive rules;
- `src/data/task-data.js` — in-memory задачи и demo-справочник ответственных;
- `src/app/app.js` — event drawer, исходное событие и закрытие конфликтующих слоев;
- `assets/images/task-create-header.png` — текущий header-баннер;
- `assets/images/assignees/` — demo-аватары ответственных.

Автоматического `*.test.mjs` для feature сейчас нет.

## Публичный интерфейс

`task-drawer.js` регистрирует `window.SCenterTasks` и не запускает контроллер автоматически.

```js
const taskController = window.SCenterTasks.createController({
    taskData: window.taskData,
    getEventById,
    renderEventDrawer,
    renderEventFeed,
    closeConflictingPanels,
    refreshIcons: () => lucide.createIcons()
});
```

Обязательные зависимости — `taskData`, `getEventById` и `renderEventDrawer`. Остальные callbacks опциональны.

Контроллер предоставляет:

- `enterEventDetail(eventOrId)` — фиксирует активное событие и переводит feature в режим события;
- `getTaskCountForEvent(eventId)` — возвращает число связанных задач;
- `renderLinkedTaskCards(eventOrId)` — возвращает HTML карточек задач для вставки после описания события;
- `handleCloseRequest()` — в task-режиме возвращает карточку события и сообщает `true`; в event-режиме возвращает `false`, после чего основной слой может закрыть drawer;
- `reset()` — очищает UI-состояние при закрытии drawer;
- `destroy()` — снимает обработчики контроллера;
- `getMode()` — возвращает текущий режим.

Контракт `taskData`:

- `getAssigneesForProject(projectId)`;
- `getAssigneeById(id)`;
- `getTasksForEvent(eventId)`;
- `getTaskById(taskId)`;
- `getTaskCountForEvent(eventId)`;
- `createTask(input)`;
- `updateTask(taskId, input)`;
- `deleteTask(taskId)`.

## Интеграционный контракт

Основной слой приложения должен:

1. Подключить `task-data.js`, затем `task-drawer.js`, затем `app.js`; подключить `task-drawer.css` после глобальных стилей.
2. После формирования детальной карточки вызвать `taskController.enterEventDetail(event)`.
3. Вставить `taskController.renderLinkedTaskCards(event)` непосредственно после описания события.
4. Передать кнопке в footer атрибуты `data-task-action="create-task"` и `data-task-create-entry="footer"`. Отдельная строка «Создать задачу» в body карточки события не используется.
5. Перед закрытием по крестику или overlay вызвать `handleCloseRequest()`. Если получен `false`, выполнить обычное закрытие drawer и затем `reset()`.
6. Добавлять `getTaskCountForEvent(event.id)` в view model компактной карточки события.

Карточки задач в детальной карточке события являются статичными информационными карточками и не кликаются целиком. В правой части карточки находятся две компактные icon-кнопки: `edit-task` для перехода в режим `task-edit` и `delete-task` для удаления задачи из текущего in-memory слоя. Остальные внутренние действия — `cancel-task-form`, `submit-task`, `save-task` и `assign-from-project-team`. Обработка делегирована одному контроллеру.

### Межкомпонентные переходы

| Источник | Условие | Результат | Получатель и конечное состояние |
| --- | --- | --- | --- |
| Event drawer | Нажата footer-кнопка `Создать задачу` | Controller переходит в `task-create` | Тот же `#event-drawer` показывает пустую форму |
| Форма задачи | Валидный submit | `taskData.createTask()` и перерисовка | Возврат в `event-detail`, карточка задачи и индикатор события обновлены |
| Карточка задачи | Нажата edit-кнопка | Controller переходит в `task-edit` | Форма заполнена текущими данными задачи |
| Карточка задачи | Нажата delete-кнопка | Задача удаляется из in-memory слоя | `event-detail` остается открыт, карточки и индикатор перерисованы |
| Cancel, close, overlay или `Escape` | Открыт `task-create` или `task-edit` | Несохраненный draft отбрасывается | Возврат к исходному `event-detail` |
| Закрытие event drawer | Активен `event-detail` | Основной слой закрывает drawer и вызывает `reset()` | Task-controller не хранит активный UI-режим |

## Поведение и состояния текущей реализации

- Название, описание и ответственный обязательны. Проверка запускается при попытке создать или сохранить задачу, показывает общий warning, inline-ошибки и переводит фокус на первое ошибочное поле.
- Название ограничено 128 символами, описание — 4000. Высота описания по умолчанию и минимальная высота равны `230px`.
- Dropdown ответственных имеет максимальную высоту `250px`, открывается вниз, а при недостатке места — вверх. При переполнении используется вертикальный scroll.
- Окно команды проекта открывается слева от drawer с резервом `690px`, не превышает `600px` по высоте и отображает ФИО, роль, должность и email. Тело таблицы использует строки и ячейки высотой `68px`; header таблицы сохраняет собственную высоту. Колонка `Фамилия, имя и отчество` расширена до `250px`, то есть на `30px` относительно прежней минимальной ширины. В этой колонке перед именем отображается круглый `42×42px` photo-like face-only avatar из справочника ответственных с учетом пола человека. Runtime-изображения хранятся как низкоразмерные PNG `42×42px` с минимальным светлым фоном в `assets/images/assignees/`; изображение содержит только лицо, соответствует размеру круглой подложки аватарки и не использует векторную стилистику. Email по умолчанию отображается синим цветом, а подчеркивание появляется только при hover. Изначально строка не выбрана, а кнопка «Назначить» неактивна.
- `Escape` сначала закрывает dropdown или окно команды. Следующий `Escape` в task-режиме возвращает карточку события.
- Отмена, крестик и overlay в `task-create` и `task-edit` отменяют несохранённый черновик и возвращают событие.
- При входе в task-режим вызывается `closeConflictingPanels`, чтобы основной слой закрыл BI, метрики, фильтры и AI-панели.
- Карточки задач под описанием события выводятся без заголовка секции и без числового индикатора. Сама карточка задачи не имеет зеленой обводки, не имеет стрелки перехода и стилистически соответствует карточке `Влияние на метрику`: нейтральная белая карточка, иконка с подложкой `44px` и иконка `24px`. Зеленый оттенок сохраняется только у task-метафоры и действий. Компактная карточка события показывает только метафору наличия хотя бы одной задачи.
- На ширине до `760px` окно команды занимает доступную область экрана, а footer формы переносит кнопки без горизонтального переполнения.

## Пространственный контракт

- Форма задачи заменяет содержимое существующего `#event-drawer` и не открывает второй drawer.
- Dropdown ответственного имеет `position: fixed`, слой `1003`, максимальную высоту `250px` и выбирает направление вверх или вниз по доступному месту.
- Окно команды использует viewport-layer `.task-project-team-layer` со слоем `2402`; desktop оставляет справа резерв `690px` под drawer, чтобы modal и drawer не перекрывали друг друга.
- Overlay окна команды принимает клики только слева от drawer; сама modal остается интерактивной.
- При открытии task-режима конфликтующие BI, filters, metrics и AI-поверхности закрываются.
- `Escape` закрывает сначала локальный dropdown/modal, затем возвращает task-режим к событию; закрытие события выполняет основной слой.
- На viewport до `760px` окно команды занимает доступную ширину, а footer переносится без горизонтального scroll.

## Будущая модель

Постоянное хранение, backend/API, workflow статусов, история изменений, реальные проектные команды, права назначения, подтверждение потери draft и batch-create не входят в текущий feature. Их реализация требует отдельного плана и синхронизации `docs/entity-model.md`, `docs/access-control.md` и roadmap.

## Acceptance

Ручная проверка:

1. `Создать задачу` открывает `task-create` в том же drawer.
2. Пустой submit показывает общий warning, inline-ошибки и фокусирует первое поле.
3. Dropdown и окно команды позволяют выбрать ответственного; `Escape` закрывает верхний локальный слой.
4. Валидное создание возвращает событие, добавляет карточку задачи и индикатор компактной карточке.
5. Edit сохраняет изменения, delete удаляет только Task, cancel/overlay/close не сохраняют draft.
6. Переключение контекста сохраняет задачи до reload страницы; reload очищает in-memory данные.
7. Desktop и viewport до `760px` не имеют перекрытия modal/drawer и горизонтального переполнения.

Автоматическое покрытие отсутствует; при изменении controller нужен локальный тест режимов, validation и обновления связанной карточки.
