# Модель сущностей интерфейса

## Цель

Этот документ фиксирует первый единый атрибутивный слой проекта. На текущем этапе в него входят две активные сущности: событие и финансовая метрика.

Слой данных расположен в `src/data/app-data.js` и подключается до `src/app/app.js`. Проект остается на обычных `<script>`, без ES-модулей и без сборщика.

## Сущность события

Событие описывает факт, риск, изменение или информационное уведомление, которое отображается в ленте, детальной карточке и участвует в фильтрации.

Закрепленный атрибутивный состав:

| Атрибут | Назначение |
| --- | --- |
| `id` | Уникальный идентификатор события. |
| `type` | Тип сущности; для текущего слоя всегда `event`. |
| `priority` | Приоритет события: `high`, `critical`, `low`. |
| `sourceId` | Ссылка на источник события из каталога источников. |
| `sourceName` | Отображаемое имя источника. |
| `sourceIcon` | Иконка источника для карточек и drawer. |
| `title` | Заголовок события. |
| `text` | Основное описание события. |
| `dateText` | Текстовое представление даты и времени. |
| `projectId` | Ссылка на проект, к которому относится событие. |
| `queueId` | Ссылка на очередь проекта. |
| `queue` | Отображаемое название очереди. |
| `objectType` | Тип объекта, например корпус. |
| `objectName` | Отображаемое имя объекта. |
| `metricId` | Ссылка на финансовую метрику, на которую влияет событие. |
| `metricName` | Отображаемое имя метрики. |
| `impact` | Текстовое значение влияния. |
| `impactValue` | Числовое значение влияния для пересчета метрик. |
| `impactUnit` | Единица влияния, извлеченная из `impact`. |
| `impactType` | Тип влияния: `positive`, `negative`, `neutral`. |
| `excluded` | Состояние исключения события из выдачи. |
| `pinned` | Состояние закрепления события. |

## Представления события

Краткое представление используется карточкой в ленте. Оно выводит источник, иконку, заголовок, дату, описание, метрику, влияние, приоритет и состояния закрепления/исключения.

Расширенное представление используется детальной карточкой. Оно добавляет проект, очередь, тип объекта, объект, расширенное отображение источника, приоритета и связанной метрики.

Оба представления собираются из одной сущности события через функции слоя данных. Компоненты не должны хранить собственные копии этих значений.

## Сущность финансовой метрики

Финансовая метрика описывает показатель в древовидной структуре. Одна и та же структура используется правой панелью, drawer структуры метрик, фильтром и BI-графиком.

Закрепленный атрибутивный состав:

| Атрибут | Назначение |
| --- | --- |
| `id` | Уникальный идентификатор метрики. |
| `name` | Отображаемое имя метрики. |
| `parentId` | Идентификатор родительской метрики; у корня `null`. |
| `fact` | Фактическое значение. |
| `plan` | Плановое значение. |
| `forecast` | Прогнозное значение. |
| `delta` | Отклонение. |
| `deltaPrevMonth` | Отклонение относительно предыдущего месяца. |
| `risk` | Признак риска. |
| `budgetImpact` | Направление влияния на бюджет: `+` или `-`. |
| `children` | Дочерние метрики. |

## Правила пересчета

При исключении события его `impactValue` применяется в обратную сторону. При возврате события значение применяется снова.

Пересчет выполняется по цепочке от целевой метрики к корню дерева. Это значит, что изменение целевой метрики отражается не только на ней, но и на родительских сводных показателях.

## Компоненты-потребители

| Область интерфейса | Какие данные использует |
| --- | --- |
| Лента событий | Краткое представление события. |
| Детальная карточка события | Расширенное представление события. |
| Фильтр | Каталог источников, приоритеты и дерево метрик. |
| Правая панель метрик | Активная метрика и ее дочерние показатели. |
| Структура метрик | Полное дерево финансовых метрик. |
| BI-график | Выбранная метрика из общего дерева. |

## Ограничения этапа

Проекты и строительные показатели пока остаются в текущей логике приложения. В событиях используются только ссылочные поля `projectId` и `queueId`.

Поврежденная русская кодировка старых интерфейсных текстов не восстанавливается в этом этапе.

Публичные глобальные интерфейсы `window.*` сохраняются, чтобы не ломать уже подключенные компоненты.
