# Состояния компонентов интерфейса

## Назначение

Документ фиксирует рабочую классификацию состояний компонентов S.Center. В исходных материалах нет единой абстрактной классификации UI-состояний, поэтому этот документ не является цитатой из источников. Это проектное правило, собранное из поведения конкретных продуктовых элементов: карточек событий, drawer, метрик, дерева навигации и аналитики.

Состояние компонента должно описывать не только визуальный вид, но и влияние на данные, пользовательский путь и связанные сценарии.

## Список состояний

| Состояние | Где применяется | Правило |
| --- | --- | --- |
| `hidden` / скрытый | События низкого приоритета, блок ML-влияния в детальной карточке, лоадеры и временно недоступные блоки. | Компонент или блок не отображается, чтобы не перегружать интерфейс. Скрытие не должно уничтожать сущность или ее данные. |
| `excluded` / исключенный | Карточка события в отфильтрованной выдаче. | Событие скрывается из текущей экранной выборки и не попадает в массовый ИИ-анализ. Сущность не удаляется из базы и не меняет числовые значения метрик. |
| `pinned` / закрепленный | Карточка события и вкладка закрепленных событий. | Событие получает статус важного для пользователя. Оно может отображаться с индикацией закрепления и попадать во вкладку `Закрепленные`. |
| `empty` / пустой | Пустые вкладки, drawer до загрузки данных, отсутствующие значения метрик. | Интерфейс показывает отсутствие данных или оставляет контейнер пустым, если заглушка создаст визуальный шум. Для AI/drawer-сценариев до готовности данных допустимо пустое пространство без skeleton UI. |
| `selected` / выбранный | Строка дерева, выбранный сегмент-контрол или таб; выбранная метрика сохраняется только как расчетный контекст после изоляции правой панели. | Выбранный элемент задает текущий фокус интерфейса: активный структурный контекст, активную вкладку или активный режим. |
| `active` / активный | Табы, сегмент-контролы, кнопки режима, раскрытые элементы дерева. | Активное состояние показывает текущий рабочий режим и должно быть синхронизировано с данными, которые реально отображаются. |
| `collapsed` / свернутый | Длинное описание события в детальной карточке. | Текстовая сущность не меняется, но визуальная область ограничивается по высоте. Для карточки `Описание события` предел всего свернутого блока — `350px`; если естественная высота больше, появляется кнопка раскрытия. |
| `expanded` / развернутый | Длинное описание события в детальной карточке, раскрытые элементы дерева. | Компонент показывает полный объем содержимого и должен иметь понятный способ возврата в свернутое состояние. Для описания события кнопка `Дополнительно` меняет стрелку вниз на стрелку вверх. |
| `invalid` / невалидный | Обязательные поля формы задачи. | После попытки сохранения незаполненное поле получает сообщение об ошибке, а фокус переводится к первой ошибке; сущность Task не создаётся и не обновляется. |

Для состояния `pinned` действует дополнительное продуктовое правило: закрепляться может не только исходное событие, но и ценный результат ИИ-аналитики, если он представлен пользователю как карточка или сохраненный вывод. Закрепление не меняет данные события и не пересчитывает метрики; оно сохраняет элемент в быстром доступе, добавляет визуальную индикацию и делает его доступным во вкладке или папке закрепленных элементов.

## Правила по компонентам

| Компонент или сценарий | Ключевые состояния |
| --- | --- |
| Карточка события | `pinned`, `excluded`, `hidden`, приоритетное состояние, `has-linked-task` при наличии связанной задачи. |
| Детальная карточка события | `event-detail`, `task-create`, `task-edit`, `open`, `collapsed/expanded` для длинного описания события, `hidden` для блока ML-влияния, `empty/loading` до готовности данных. |
| BI-график метрики | `closed`, `open`, прогноз `off/on`, hover выбранного месяца, `side-by-side` рядом с event drawer или полноэкранная модалка на ограниченной ширине. |
| Форма задачи | `task-create`, `task-edit`, `invalid`, открытый/закрытый dropdown ответственного. |
| Окно команды проекта | `open`, отсутствие выбора, выбранный radio, доступная/недоступная кнопка `Назначить`. |
| Лента событий | `empty` для отсутствия карточек, `filtered` для примененной выборки. |
| Левое структурное дерево | `selected`, `active`, `expanded`, `collapsed`. |
| Drawer структуры метрик | Изолирован в `legacy/isolated/right-metrics-panel/`; не входит в активные состояния прототипа. |
| Правая панель метрик | Изолирована в `legacy/isolated/right-metrics-panel/`; не входит в активные состояния прототипа. |
| EventToolbar | `default`, `filtered`, активная вкладка; в режиме `Метрики` скрывает событийный поиск, аналитику и фильтр, сохраняя ассистента. |
| MetricsDashboard | `loading`, `ready`, активный внутренний раздел, `unsupported-context`, недоступный внутренний раздел; локальное переключение меняет состояния вкладок и постоянный `tabpanel` без перемонтирования навигации; будущие интеграционные состояния: `partial`, `empty`, `error`, `stale`, `restricted`. |
| Dropdown `Цифровая шахматка` | `closed`, `open`, `dashboard`, `digital-chessboard-summary`, `digital-chessboard`, `objects`; `ArrowUp/Down`, `Home`, `End`, `Escape` и `Tab` синхронизируют `aria-expanded`, `aria-current` и фокус. |
| Сводка цифровой шахматки | `loading`, `ready`, `empty`, `unsupported-context`, `table-error`, `attention-error`, `archive-ready`, `archive-empty`, `archive-error`, `archive-snapshot`, `print`, `detail`; project selector, row disclosure/menu, tooltip и filter-state; `hide` закрывает overlay и общий table-scroll controller. |
| Цифровая шахматка | `ready`, `unsupported-context`, `single-work`, `empty-work`, `comparison-draft`, `comparing`, `fact`, `fact-plan`, `date-draft`; модальные состояния удерживают и возвращают фокус, а feature переключается через `hidden`/`show`/`hide` без перемонтирования. |
| Объекты | `ready`, `unsupported-context`, выбранный объект, раскрытые/свернутые группы, quick-filter, filter-draft, filtered, no-results, filter-dialog, announcement; `hide` закрывает локальные overlay/drag, но сохраняет безопасное локальное состояние. |
| AI-аналитика | `empty/loading`, `ready`, анализ только текущей очищенной выдачи. |

## Правило документации

В источниках нет готового регламента, какие изменения компонентов должны обязательно отражаться в документации. Для проекта S.Center принимается собственное правило:

Документация обновляется вместе с кодом, если изменение влияет хотя бы на один из пунктов:

- назначение компонента;
- состав входных или отображаемых данных;
- состояние компонента и условия перехода между состояниями;
- пользовательское действие или пользовательский путь;
- связь компонента с `src/data/`, `src/app/` или публичными `window.*` интерфейсами;
- влияние компонента на фильтрацию, выборку, аналитику, метрики или активный контекст;
- визуальное поведение, которое меняет смысл работы пользователя.

Если правка является только внутренней технической оптимизацией и не меняет внешний смысл, данные, состояния или путь пользователя, достаточно указать это в итоговом сообщении без изменения документации.
