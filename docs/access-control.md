# Права доступа и видимость данных

## Назначение

Документ фиксирует, как ролевая модель S.Center ограничивает видимость бизнес-юнитов, проектов, очередей, метрик, событий и действий пользователя.

Главный принцип: интерфейс не должен просто скрывать лишнее визуально. Пользовательские компоненты должны получать уже подготовленную выборку данных, соответствующую роли, правам и активному контексту пользователя.

## Базовое правило

Видимость данных определяется сочетанием четырех факторов:

| Фактор | Что определяет |
| --- | --- |
| Роль пользователя | Общий профиль доступа: РП, топ-менеджмент, планировщик, контрольная служба, подрядчик. |
| Зона ответственности | Какие бизнес-юниты, проекты и очереди доступны пользователю. |
| Тип данных | Финансовые, строительные, событийные, управленческие или справочные данные. |
| Контекст события | Источник события, объект, метрика, подрядчик, тип инцидента и доступные действия. |

## Уровни доступа

| Уровень | Правило видимости | Примеры |
| --- | --- | --- |
| Бизнес-юниты, проекты, очереди | Дерево навигации показывает только те узлы, которые входят в зону ответственности пользователя. | Директор кластера видит все проекты своего кластера или бизнес-юнита. РП видит только закрепленные за ним проекты. Внутри проекта пользователь может спускаться на уровень очереди. |
| Метрики | Дерево метрик и правый блок показателей должны учитывать коммерческую чувствительность данных. | Финансовые метрики: маржа, чистая прибыль, продажи, доходы и налоги скрываются от планировщиков и внешних подрядчиков. Им могут показываться строительные метрики: длительность, объемы работ, статусы и физический прогресс. |
| События | Лента событий фильтруется по роли, источнику, типу события и доступному контексту. | Планировщики видят события из Gantt, MS Project и S.Pass. Специалисты по охране труда могут видеть только события по безопасности из Control. Подрядчик видит только события своего объема работ. |
| Действия | Доступные действия зависят от роли и смысла конкретного события. | РП может создать задачу, запросить обоснование или связаться с подрядчиком. Планировщику релевантен переход в график. Подрядчику доступны только действия в рамках его работ. |

## Правила для реализации

- Фильтрация по правам должна происходить до передачи данных в компоненты интерфейса.
- Компонент не должен самостоятельно решать, какие закрытые данные скрывать; он отображает разрешенную модель данных.
- Скрытие финансовых и коммерческих данных нельзя реализовывать только через CSS или удаление текста из DOM после рендера.
- Контекстный выбор бизнес-юнита, проекта или очереди применяется внутри уже разрешенной пользователю области.
- Метрики, события и действия должны проверяться отдельно: доступ к проекту не означает автоматический доступ ко всем финансовым метрикам проекта.
- Документация компонента должна указывать, если компонент зависит от роли пользователя или прав доступа.

## Связь с интерфейсом

| Область интерфейса | Как применяется доступ |
| --- | --- |
| Левое дерево навигации | Показывает только доступные бизнес-юниты, проекты и очереди. |
| Центральная лента событий | Получает события только из разрешенного контекста и разрешенных источников. |
| Фильтр событий | Не должен предлагать значения, которые ведут к закрытым данным. |
| Правая панель метрик | Показывает только разрешенные финансовые или строительные показатели. |
| Структура метрик | Отображает только доступные ветки дерева метрик. |
| Детальная карточка события | Показывает расширенный состав события только в рамках разрешенных атрибутов. |
| AI-аналитика | Анализирует только те события и метрики, которые доступны пользователю. |

## Известные правила по ролям

| Роль | Доступ к иерархии | Доступ к метрикам | Доступ к событиям |
| --- | --- | --- | --- |
| Руководитель проекта | Свои проекты и очереди. | Метрики в зоне влияния РП, например валовая прибыль и строительные показатели. | Оперативные события по своим объектам. |
| Топ-менеджмент | Бизнес-юниты, кластеры, портфель проектов в зоне ответственности. | Агрегированные финансовые и строительные показатели, включая чистую прибыль. | События по доступному портфелю, в том числе для верхнеуровневого анализа. |
| Планировщик | Проекты и очереди, связанные с планированием. | Строительные и календарные показатели; финансовые метрики скрыты. | События по срокам, графикам и контролю доступа из Gantt, MS Project и S.Pass. |
| Контрольные службы | Объекты и участки в зоне профильного контроля. | Показатели, связанные с качеством, безопасностью, приемкой и статусами работ. | Профильные инциденты: безопасность, нарушения, штрафы, замечания, приемка работ. |
| Внешний подрядчик | Только свой объем работ. | Только строительные показатели, относящиеся к его работам. | Только собственные строительные задачи и события; коммерческие и управленческие данные скрыты. |
