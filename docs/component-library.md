# Внутренняя библиотека компонентов

## Назначение

В проекте формируется внутренняя UI-библиотека. Она нужна, чтобы повторяющиеся элементы интерфейса собирались из единых строительных блоков, а не переписывались заново внутри сценариев.

## Уровни структуры

| Уровень | Назначение |
| --- | --- |
| `src/ui/` | Базовые нейтральные элементы и хелперы. Они не знают про события, проекты и метрики. |
| `src/components/` | Предметные повторяемые компоненты: карточки, строки дерева, карточки метрик. |
| `src/features/` | Пользовательские сценарии: фильтрация, аналитика, дерево метрик, BI. |
| `src/data/` | Данные сущностей, атрибуты и значения. |
| `src/app/` | Связка приложения и текущий orchestration-слой. |

## Правило нейминга

Имя компонента должно показывать смысловую связь:

`ОбластьИнтерфейса + Сущность + Роль`

Примеры:

| Имя | Смысл |
| --- | --- |
| `NavigationTreeItem` | Строка дерева в левом навигационном сайдбаре. |
| `FinancialMetricSummaryCard` | Главная карточка активной финансовой метрики. |
| `FinancialMetricChildCard` | Мини-карточка дочерней финансовой метрики. |
| `ConstructionMetricCard` | Карточка строительного показателя. |

Такой нейминг помогает человеку и модели понимать, что является родительским компонентом, а что его частью.

## Текущий этап

На текущем этапе компоненты возвращают HTML-строки и используют существующие CSS-классы. Это сохраняет визуальное поведение проекта и не требует перехода на сборщик или ES-модули.

Подключение остается через обычные `<script>`. Общие функции доступны через `window.SCenterUI`, а предметные компоненты через `window.SCenterComponents`.
