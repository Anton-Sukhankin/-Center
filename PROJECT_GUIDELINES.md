# Правила проекта

## Назначение документа

Этот документ задает общие правила работы с проектом. Он не заменяет документацию компонентов, данных или сценариев, а связывает их в единую систему.

Правило верхнего уровня: код, данные и документация должны развиваться вместе. Если изменение в коде меняет смысл компонента, его данные, состояния или пользовательский путь, соответствующая документация обновляется в том же этапе работ.

## Основная структура

| Область | Назначение |
| --- | --- |
| `src/data/` | Единые источники данных, сущности, атрибуты, расчетные функции и контекстные выборки. |
| `src/ui/` | Базовые UI-хелперы, не завязанные на предметные сущности. |
| `src/components/` | Повторяемые визуальные компоненты интерфейса: карточки, строки дерева, тулбары, панели действий. |
| `src/features/` | Пользовательские сценарии: фильтры, структура метрик, BI, аналитика. |
| `src/app/` | Связующий слой приложения: активный контекст, порядок рендера, глобальные сценарии и интеграция компонентов. |
| `docs/` | Общая проектная документация, карты компонентов, модели сущностей, планы и архив решений. |

## Правило синхронизации документации

Документация должна обновляться вместе с кодом, если изменение затрагивает хотя бы один пункт:

- назначение компонента или сценария;
- состав входных данных;
- состав отображаемых данных;
- пользовательские действия;
- состояния компонента;
- публичные `window.*` интерфейсы;
- связь с `src/data/`;
- роль компонента в пользовательском пути;
- визуальные ограничения, влияющие на поведение интерфейса;
- порядок подключения файлов в `index.html`.

Если изменение является только внутренней технической правкой и не меняет внешний смысл компонента, достаточно указать это в итоговом сообщении без правки документации.

## Где фиксировать изменения

| Тип изменения | Где обновлять документацию |
| --- | --- |
| Изменился визуальный компонент | `src/components/<component>/README.md` и при необходимости `docs/component-map.md`. |
| Изменился пользовательский сценарий | `src/features/<feature>/README.md` и при необходимости `docs/component-map.md`. |
| Изменились сущности, атрибуты или расчеты | `src/data/README.md`, `docs/entity-model.md` или актуальный план в `docs/plans/`. |
| Изменился связующий сценарий приложения | `src/app/README.md` и при необходимости `docs/app-decomposition-map.md`. |
| Изменились общие правила проекта | `PROJECT_GUIDELINES.md`. |

## Правила данных

Компоненты не должны хранить собственные копии сущностей. Они получают данные из общего слоя:

- события, источники, приоритеты, финансовые метрики и строительные показатели: `src/data/app-data.js`;
- бизнес-юниты, проекты, очереди и активные контекстные области: `src/data/project-structure.js`.

Если один и тот же атрибут показывается в нескольких местах интерфейса, его источник должен быть единым.

## Правила компонентов

Компонент отвечает за отображение и локальное поведение своего элемента интерфейса. Он не должен самостоятельно решать, какие события, проекты или метрики входят в текущую выборку.

Крупный пользовательский сценарий не считается простым компонентом. Например, фильтрация, структура метрик, BI-модалка и AI-аналитика документируются в `src/features/`, даже если внутри них есть визуальные блоки.

## Публичные интерфейсы

Проект пока работает через обычные `<script>` без ES-модулей. Поэтому публичные точки интеграции через `window.*` считаются контрактом.

Нельзя менять или удалять публичные интерфейсы без отдельного этапа:

- `window.filterState`;
- `window.toolbarState`;
- `window.metricsData`;
- `window.activeContext`;
- `window.renderEventFeed`;
- `window.openFilterDrawer`;
- `window.openTreeDrawer`;
- `window.openBIModalV2`;
- `window.aiInsights`;
- `window.appData`;
- `window.projectStructureData`;
- `window.SCenterUI`;
- `window.SCenterComponents`.

## Проверки после изменений

Минимальная проверка после изменения кода:

- проверить синтаксис всех JS-файлов;
- проверить, что локальные подключения из `index.html` существуют;
- проверить основной пользовательский сценарий, который затронут изменением;
- если менялись данные, проверить, что компоненты-потребители получают значения из одного источника;
- если менялся компонент, проверить все места, где он используется.

## Карты и паспорта

Основные точки входа в документацию:

- `docs/component-map.md` — карта компонентов, сценариев, данных и пользовательских путей;
- `src/data/README.md` — слой данных и расчетов;
- `src/app/README.md` — связующий слой приложения;
- `src/components/*/README.md` — паспорта визуальных компонентов;
- `src/features/*/README.md` — паспорта пользовательских сценариев.
