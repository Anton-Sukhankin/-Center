# План: возврат дерева метрик

Статус: `завершен`  
Документ подчиняется `docs/plans/README.md` и хранится как история выполненного этапа.

## Goal

Вернуть в активный интерфейс AIShtab правый drawer древовидной структуры метрик и добавить для него вторичную кнопку `Структура метрик` в тулбаре активного раздела `Метрики`, сохранив переход к действующему BI-графику выбранного показателя.

## Context

Исходный drawer и его визуальный слой были сохранены в `legacy/isolated/right-metrics-panel/`. Расчетное дерево `window.metricsData`, выбранный `window.activeMetricId` и BI-сценарий уже оставались активными. Центральный дашборд `Метрики` использует отдельную view model и не меняет состав финансового дерева.

## Scope

- активный feature `src/features/metrics/` для drawer структуры;
- secondary-кнопка `Структура метрик` перед кнопкой `Задать вопрос`, видимая только во вкладке `Метрики`;
- раскрытие и сворачивание веток, выбор строки и отдельная кнопка открытия BI-графика;
- закрытие drawer по overlay, кнопке и `Escape`, возврат фокуса и разрешение конфликта с AIShtab;
- обновление дерева при смене проектного контекста.

## Out of Scope

- возврат прежней правой панели карточек метрик;
- изменение `src/data`, состава дерева или расчетной арифметики;
- объединение дерева с показателями `Общие` и `Закупки` центрального дашборда;
- реальные исторические данные и промышленный прогноз BI.

## Constraints

- сохранены активные `window.openBIModalV2`, `window.openChartWidget`, `window.onMetricClick` и `window.setActiveMetricId`;
- архивная копия BI не подключена;
- демонстрационные данные дерева не изменены;
- drawer ассистента и drawer дерева не остаются открыты одновременно;
- UI сохраняет клавиатурный путь и возврат фокуса.

## Impact

Затронуты `EventToolbar`, `src/app`, активный BI, новый активный feature дерева, `index.html` и документационные карты. По `docs/component-impact-map.md` риск высокий из-за общего состояния метрик, публичных `window.*` и модальных слоев.

## Выполненные шаги

1. Изолированный drawer адаптирован в активный feature без возврата правой панели.
2. CSS и JS подключены в `index.html` до `src/app/app.js`.
3. В `EventToolbar` добавлена контекстная secondary-кнопка.
4. Stub `window.openTreeDrawer` заменен активным контрактом feature; дерево обновляется после пересчета текущего контекста.
5. Проверены дерево, BI, прогноз, закрытие, фокус, конфликт с AIShtab и режимы тулбара.
6. Паспорта, карты, матрица и roadmap синхронизированы.

## Acceptance Criteria

- кнопка видима только при активной вкладке `Метрики` и расположена перед `Задать вопрос`;
- кнопка открывает правый drawer дерева текущего контекста;
- родительские ветки раскрываются и сворачиваются независимо;
- строка выбирает показатель, а правая action-кнопка открывает BI именно этого показателя;
- BI открывается с drawer, переключает прогноз и закрывается без закрытия дерева;
- закрытие дерева закрывает дочерний BI и возвращает фокус в trigger;
- открытие AIShtab закрывает дерево, программное переключение вкладки также закрывает дерево;
- отсутствуют новые ошибки консоли, а синтаксис измененных JS-файлов корректен.

## Verification

- `node --check` пройден для `metric-drawer.js`, `event-toolbar.js` и `app.js`;
- локальные подключения `index.html` существуют;
- Chrome через bundled Playwright подтвердил 18 строк, раскрытие корня, открытие BI для `Выручка`, прогноз, сохранение дерева после закрытия BI, закрытие по `Escape`, возврат фокуса и конфликт с AIShtab;
- viewport `1660 × 950` подтвердил side-by-side BI и drawer;
- viewport `1280 × 800` подтвердил отсутствие пересечения кнопок и нахождение drawer внутри viewport;
- внешние font и Lucide-запросы в headless-проверке заменены локальным test shim из-за сетевой недоступности; это не меняло код проекта.
