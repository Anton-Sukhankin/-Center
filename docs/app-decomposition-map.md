# Карта будущей декомпозиции `src/app/app.js`

## Цель

Разделить большой файл `src/app/app.js` только после стабилизации текущей логики. Проект по-прежнему работает на обычных `<script>` без ES-модулей и без сборщика.

Первым устойчивым слоем выделен `src/data/app-data.js`. Он хранит атрибутивные данные событий и финансовых метрик, а также функции получения кратких и расширенных представлений.

## Зоны ответственности

| Зона | Что входит | Текущий статус |
| --- | --- | --- |
| Данные приложения | События, источники событий, приоритеты, финансовые метрики, представления сущностей. | Вынесено в `src/data/app-data.js` для событий и метрик. |
| Базовый UI-слой | Нейтральные хелперы и строительные блоки интерфейса. | Создан `src/ui/ui-core.js`; функции доступны через `window.SCenterUI`. |
| Компоненты интерфейса | Предметные повторяемые элементы: строки навигации, карточки событий, тулбары и панели действий. | Активные компоненты находятся в `src/components`; изолированные карточки метрик перенесены в `legacy/isolated/right-metrics-panel/`. |
| Навигация проекта | Дерево бизнес-юнитов, проектов и очередей, выбор активной сущности, поиск слева. | Пока остается в `src/app/app.js`. |
| Навигация основных экранов | Переключение `Сводный дашборд` / `Сводка` / `Шахматка` / `Объекты`, доступный dropdown, active-state header и сохранение четырех смонтированных поверхностей. | Минимальный whitelist screen-controller остается в `src/app/app.js`; предметная логика вынесена в `src/features/digital-chessboard-summary/`, `src/features/digital-chessboard/` и `src/features/objects/`; общий selector объектов и общий table-contract находятся в `src/components/`. |
| Лента событий | Фильтрация, вкладки, счетчики, карточки, закрепление, скрытие и возврат событий. | Использует данные из `src/data/app-data.js`, но логика рендера остается в `src/app/app.js`. |
| Детальная карточка события | Drawer события, параметры, описание, действия, карточка влияния на метрику. | Использует расширенное представление события из слоя данных. |
| Создание, редактирование и удаление задачи | Режимы `task-create`/`task-edit`, форма, dropdown, окно команды, статичные карточки связанных задач и icon-действие удаления. | Вынесено в `src/features/tasks/`; контроллер доступен через `window.SCenterTasks`, runtime-данные и `deleteTask(taskId)` — через `window.taskData`. |
| Фильтры | Источники, приоритет, период и дерево метрик. | Источники и метрики берутся из общего слоя данных. |
| Метрики | Расчетные данные, связь событий с `metricId`, фильтр по метрикам, центральный `MetricsDashboard`, активный BI-график и stub бывшего metric drawer. | Центральный dashboard вынесен в `src/features/metrics-dashboard/`, BI-график — в `src/features/bi/`; правая панель и drawer структуры метрик остаются изолированными. |
| Общие утилиты | Форматирование валюты, поиск сущностей, генерация мини-графиков. | Можно выделять после отделения навигации и рендера. |

## Минимальный безопасный порядок

1. Закрепить слой данных для событий и метрик.
2. Перенести проектную навигацию в отдельную область только после проверки ленты событий.
3. Вынести рендер ленты событий и карточки события.
4. Стабилизировать общий drawer с режимами события и задачи; не возвращать task-логику в `app.js`.
5. Не возвращать правую панель метрик без отдельного плана интеграции из `legacy/isolated/right-metrics-panel/`.

## Ограничения

- Не менять публичные `window.*` интерфейсы до отдельного решения о модульной архитектуре; текущие `window.taskData` и `window.SCenterTasks` считаются документированными контрактами классических скриптов.
- Крупные стабильные inline-стили генерируемой разметки постепенно переносить в CSS владельца компонента. Динамические значения оставлять inline только при обоснованной необходимости; каждый перенос проверять по итоговому layout.
- Не смешивать декомпозицию с восстановлением поврежденной русской кодировки.
- Не менять визуальную концепцию интерфейса при переносе данных.
- Проверять каждый перенос через синтаксическую проверку JS и ручные сценарии интерфейса.
