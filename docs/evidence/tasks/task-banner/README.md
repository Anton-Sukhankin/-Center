# Анализ баннера интерфейса создания задачи

## Вывод

Рекомендуемая основа — существующая композиция `assets/images/event-detail-header.png`. Геометрия, перспектива, положение блокнота, строительный фон и распределение объектов остаются неизменными.

Для состояния создания задачи меняются только два слоя:

1. Синяя палитра переводится в светло-зелёную палитру текущего баннера создания задачи.
2. Содержимое листа в блокноте заменяется с метрики на метафору задачи: крупная отметка выполнения, короткий чек-лист и элемент добавления.

## Что необходимо сохранить

- исходное соотношение сторон и композицию баннера;
- положение, размер и перспективу блокнота;
- здания, краны, графические линии, растения и оранжевые акценты;
- светлый фон и свободное пространство;
- читаемость изображения при фактической высоте шапки drawer.

## Что необходимо изменить

- выполнить единый цветовой перевод синей гаммы в светло-зелёную;
- сделать блокнот на 2–3 тона насыщеннее фонового изображения;
- сохранить белый лист блокнота;
- локально заменить только графику внутри листа на метафору создания задачи;
- не регенерировать фон и не менять расположение объектов.

## Ограничения и риски

- слишком равномерная зелёная тонировка снизит контраст блокнота относительно фона;
- смысл состояния не должен передаваться только цветом: его дублируют заголовок «Создать задачу» и текст события-основания;
- баннер является декоративным изображением и должен иметь пустой `alt`, если доступное название уже задано текстом интерфейса.
