# Связующий слой приложения

## Назначение

`src/app/app.js` связывает данные, компоненты и пользовательские сценарии. Это текущий orchestration-слой проекта.

Он отвечает за активный контекст, порядок перерисовки интерфейса и сохранение публичных `window.*` контрактов.

## Основные зоны ответственности

- инициализация данных;
- активный контекст дерева;
- выбор бизнес-юнита, проекта или очереди;
- шапка выбранного контекста;
- лента событий;
- детальная карточка события;
- пересчет финансовых метрик;
- пересчет строительных показателей;
- синхронизация правой панели, фильтров, тулбара и drawer.

## Лента событий

Центральная лента событий использует два уровня переключения:

- верхний тулбар выбирает общий набор событий: `Сегодня`, `Все события`, `Закрепленные`;
- табы под тулбаром выбирают приоритет внутри текущего набора: `Высокий приоритет` или `Низкий приоритет`.

Счетчики в табах приоритета считаются после выбора активного контекста, пользовательских фильтров и верхней вкладки событий.

В интерфейсе одновременно отображаются карточки только выбранного приоритета. Карточки второго приоритета остаются в данных текущей выборки и становятся видимыми при переключении таба.

Табы приоритета оформляются как плоская строка навигации: активный таб выделяется темным текстом и нижним индикатором, неактивный таб остается светлее. Количество событий отображается справа от названия таба на уровне текста.

Табы приоритета и список карточек находятся в едином блоке `event-feed-sections` с внутренним паддингом `16px` со всех сторон.

## Детальная карточка события

Drawer детальной карточки события открывается справа и использует ширину `690px`. Это на 150px шире предыдущей версии, чтобы расширенное описание, параметры события и блок влияния на метрику читались свободнее. BI-окно в режиме рядом с drawer использует отступ `690px` только при открытой детальной карточке события; для drawer структуры метрик сохраняется отступ `540px`.

Изображение в верхней части header хранится в `assets/images/event-detail-header.png`. После расширения drawer оно перегенерировано как широкий баннер `2400×488` с пропорцией около `4.92:1`. Композиция должна заполнять всю ширину контейнера: главный объект расположен слева, строительные элементы продолжаются через центр, а правая часть поддерживается легким графиком и объектами, чтобы изображение не обрывалось визуально.

Визуальная зона hero-изображения расширена на `50px` вправо относительно обычной ширины контента header. Это помогает показать больше горизонтальной композиции внутри шапки детальной карточки без изменения данных события и логики drawer.

## Ключевые данные

`app.js` использует:

- `window.appData`;
- `window.projectStructureData`;
- `window.activeContext`;
- `window.filterState`;
- `window.metricsData`;
- `window.activeMetricId`;
- `window.toolbarState`.

## Пользовательский путь

1. Пользователь выбирает узел в левом дереве.
2. `setActiveEntity` обновляет активный контекст.
3. События, финансовые метрики и строительные показатели пересчитываются для нового контекста.
4. Перерисовываются шапка, лента событий, табы приоритета, строительные показатели и финансовый блок.

## Важные зависимости

`app.js` должен подключаться после:

- `src/data/app-data.js`;
- `src/data/project-structure.js`;
- `src/ui/ui-core.js`;
- базовых компонентов из `src/components/`.

## Когда обновлять документ

Документ нужно обновлять, если:

- меняется порядок рендера;
- меняется активный контекст;
- меняется логика выбора узла дерева;
- меняются публичные `window.*` функции;
- часть логики переносится из `app.js` в отдельный компонент или feature.
