# Референсы «Сводки цифровой шахматки»

## Назначение

Каталог сохраняет визуальные основания интегрированного feature `Сводка` после удаления локального стенда. Материалы подтверждают принятую композицию и дизайн-решения, но не заменяют актуальные контракты в `src/features/digital-chessboard-summary/README.md`, `src/components/construction-table/README.md` и `src/data/README.md`.

## Сохраненные источники

- `source-reference.png` — исходный desktop-референс пользователя;
- `qa/reference-kpi-cards-option-2.png` — выбранное направление отдельных KPI-карточек с цветными icon-tile;
- `qa/reference-kpi-cards-option-2-crop.png` — сфокусированный фрагмент выбранного направления;
- `docs/evidence/digital-chessboard-summary/` — итоговые browser-capture интеграции, принятые сравнения и regression-capture раздела `Объекты`.

Промежуточные изображения, локальные команды запуска и диагностические API стенда не сохраняются: они не определяют актуальную функциональность.

## Принятый контракт

- глобальный header, профиль и sidebar исходного изображения не входят в feature;
- toolbar содержит самостоятельную карточку проекта и кнопки `Архив` / `Печать` без общей подложки;
- шесть KPI отображаются отдельными горизонтальными карточками с gap `8px`; после принятой постинтеграционной корректировки icon-tile `40×40px` и значение `28px / 500` занимают верхнюю строку, название параметра размещается ниже;
- блоки недельной динамики и проблем равновысокие, имеют фиксированные header/footer, внутренний scroll и полноширинные footer-actions;
- таблица сохраняет общий контракт раздела `Объекты`: header `42px`, строки и пустой footer `51px`, typography `14px`, nowrap и выравнивание влево;
- desktop-композиция адаптируется к общей оболочке и доступной ширине активного прототипа.

## Осознанные отличия интеграции

| Локальный стенд | Основной прототип | Причина |
| --- | --- | --- |
| Собственный каталог из трех demo-проектов | Canonical `window.activeContext` и список проектов от `src/app` | Один проектный контекст для всех main-view. |
| `window.DigitalChessboardSummaryData` | `window.digitalChessboardSummaryData` | Data-view интегрирован в общий `src/data`. |
| `window.digitalChessboardSummaryStand` | `window.SCenterDigitalChessboardSummary` | Диагностический stand API заменен lifecycle активного feature. |
| `?scenario=` | `?summaryScenario=` | Сценарии QA изолированы от других экранов прототипа. |
| Stand-only названия и числовые значения | Детерминированные значения canonical проекта | Фикстуры стенда не являются бизнес-методикой. |
| Синий оттенок части метафор | Нейтральные tokens общей оболочки | Принятая интеграционная адаптация без изменения геометрии и смысла. |

## Границы бизнес-интерпретации

Референсы подтверждают визуальную композицию, но не промышленную методику KPI, готовности и рисков, источник недельных событий и архивов, права, persistence, бизнес-смысл row-menu или cross-feature переход `Открыть в шахматке`. Эти ограничения описываются как будущая реализация и не выводятся из изображений.

## Проверка после удаления стенда

Актуальная реализация должна проходить data/feature-тесты, browser-сценарии `ready`, `loading`, `empty`, error/retry, архив, печать, drawers, project switch и regression раздела `Объекты`. Результаты интеграционного сравнения находятся в `docs/evidence/digital-chessboard-summary/README.md`.
