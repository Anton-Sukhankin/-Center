# Слой данных

## Назначение

`src/data/` хранит единые источники данных и расчетные функции. Компоненты не должны создавать собственные копии событий, метрик, проектов или очередей.

## Файлы

| Файл | Назначение |
| --- | --- |
| `app-data.js` | События, источники, приоритеты, финансовые метрики, строительные показатели, представления событий и расчетные функции. |
| `project-structure.js` | Дерево бизнес-юнитов, проектов и очередей, а также функции получения активного контекста. |

## Публичные интерфейсы

`window.appData` предоставляет:

- `getEventsForContext(context)`;
- `getMetricsForContext(context, events)`;
- `getConstructionMetricsForContext(context)`;
- `getEventSources()`;
- `getPriorities()`;
- `getMetricSelectorTree(metricsRoot)`;
- `getEventListViewModel(event, metricsRoot)`;
- `getEventDetailViewModel(event, metricsRoot)`;
- `findMetricById(node, id)`;
- `findMetricPathById(node, id)`.

`window.projectStructureData` предоставляет:

- `getProjectStructure()`;
- `findProjectEntityById(id)`;
- `getContextScope(type, id)`.

## Сущности

Основные сущности слоя:

- событие;
- финансовая метрика;
- строительный показатель;
- бизнес-юнит;
- проект;
- очередь;
- активный контекст.

## Типы данных в прототипе

| Тип данных | Что входит сейчас | Правило развития |
| --- | --- | --- |
| Демонстрационные данные | События, источники, приоритеты, дерево финансовых метрик, строительные показатели, бизнес-юниты, проекты и очереди. | Можно расширять для проверки интерфейса, но нельзя считать реальным промышленным источником. |
| Расчетные данные | Контекстные финансовые и строительные показатели, счетчики событий, краткое и расширенное представление события, дерево метрик для интерфейса. | Должны строиться из одного источника и не дублироваться локально в компонентах. |
| Будущие справочники | Роли, права доступа, справочник действий, справочник кодов работ и событий, источники интеграций, правила арифметики дерева метрик. | Должны быть вынесены отдельно до подключения реальных данных и AI/ML-логики. |
| Будущие интеграционные данные | События из S.Pass, Gantt, Control и других внешних систем. | Должны проходить нормализацию перед попаданием в единую модель события. |

Разделение типов данных связано с `docs/system-compliance-matrix.md`: если демонстрационная сущность становится целевой реализацией или появляется новый будущий справочник, нужно обновить матрицу и `docs/entity-model.md`.

## Связь с матрицей соответствия

Слой данных отражен в `docs/system-compliance-matrix.md` как отдельный элемент `src/data`. При изменении демонстрационных данных, расчетных функций, будущих справочников, интеграционных источников или публичных `window.appData` / `window.projectStructureData` нужно обновить этот README, `docs/entity-model.md`, `docs/component-map.md` и матрицу соответствия.

## Пользовательский путь

Пользователь выбирает узел в левом дереве. `project-structure.js` формирует активный контекст. Затем `app-data.js` возвращает события, финансовые метрики и строительные показатели только для этого контекста.

## Правило расчетной логики

Структура дерева метрик и арифметическая логика расчета не должны смешиваться в одном понятии.

Дерево метрик отвечает за декомпозицию: какие показатели являются родительскими, какие дочерними и как пользователь перемещается по структуре. Арифметическая логика отвечает за расчет: какие дочерние показатели прибавляются, какие вычитаются, какие значения агрегируются и какие параметры считаются производными.

Если в будущем появится отдельный файл или внешний источник вроде `canonical_structure_definition`, он должен описывать граф декомпозиции, но не обязан хранить всю арифметику. Правила сложения, вычитания, агрегации и прогнозного влияния должны быть зафиксированы в отдельном источнике проекта: в `src/data/README.md`, профильной документации метрик и соответствующих расчетных функциях слоя данных.

## Когда обновлять документ

Документ нужно обновлять, если:

- добавлен новый тип сущности;
- изменился атрибутивный состав события, метрики, проекта или очереди;
- изменились правила агрегации;
- изменились публичные функции `window.appData` или `window.projectStructureData`;
- компонент начал использовать новый источник данных.
